Meetly webhooks let you receive instant HTTP POST notifications when key events happen — such as when a transcription completes or action items are ready — so you can automate downstream workflows without polling.

## Supported Events

Subscribe to one or more of the following events when creating a webhook endpoint.

| Event | Description |
|-------|-------------|
| `meeting.created` | A meeting was created via the API or dashboard |
| `meeting.transcription_completed` | Transcription has finished and is available to read |
| `meeting.summary_generated` | AI summary generation is complete |
| `meeting.action_items_extracted` | Action items have been extracted from the transcript |
| `meeting.completed` | Meeting lifecycle is complete — all AI processing has finished |
| `meeting.failed` | Meeting processing failed due to an error |

## Creating a Webhook

You can create a webhook from the dashboard or via the API.

<Steps>
  <Step title="Open Webhooks settings">
    Go to **Settings → Webhooks → New Webhook** in your Meetly dashboard.
  </Step>
  <Step title="Enter your endpoint URL">
    Provide the HTTPS URL of the server that will receive webhook events. HTTP endpoints are not accepted.
  </Step>
  <Step title="Select events">
    Choose one or more events you want to subscribe to.
  </Step>
  <Step title="Save and verify">
    Click **Save**. Meetly immediately sends a test ping to your endpoint to verify it is reachable and responding with a `2xx` status code.
  </Step>
</Steps>

Alternatively, create a webhook programmatically with the API:

```bash
curl -X POST https://api.meetly.ai/v1/webhooks \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://yourdomain.com/meetly-webhook",
    "events": [
      "meeting.transcription_completed",
      "meeting.action_items_extracted"
    ]
  }'
```

## Webhook Payload

Every event Meetly sends follows the same envelope structure. Below is an example payload for the `meeting.transcription_completed` event.

```json
{
  "id": "evt_01HX...",
  "type": "meeting.transcription_completed",
  "created_at": "2024-01-15T09:35:00Z",
  "data": {
    "meeting_id": "mtg_abc123",
    "transcript_id": "trn_xyz789",
    "meeting_title": "Team Standup",
    "duration_seconds": 1820
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier for this event |
| `type` | string | The event type (see [Supported Events](#supported-events)) |
| `created_at` | string | ISO 8601 timestamp of when the event was created |
| `data` | object | Event-specific payload containing meeting details |

## Verifying Webhook Signatures

Meetly signs every webhook payload with **HMAC-SHA256** using your webhook secret. Always verify the signature before processing an event to ensure the request genuinely came from Meetly.

You can find your webhook secret in **Settings → Webhooks** next to the endpoint you created.

<Warning>
  Always verify webhook signatures before processing events. Skipping this step leaves your endpoint vulnerable to spoofed requests from malicious third parties.
</Warning>

<Tabs>
  <Tab title="Python">
    ```python
    import hmac
    import hashlib

    def verify_signature(payload: bytes, signature_header: str, secret: str) -> bool:
        expected = hmac.new(
            secret.encode("utf-8"),
            payload,
            hashlib.sha256
        ).hexdigest()
        return hmac.compare_digest(f"sha256={expected}", signature_header)

    # In your request handler:
    # payload      = request.body          (raw bytes)
    # sig_header   = request.headers["Meetly-Signature"]
    # is_valid     = verify_signature(payload, sig_header, "YOUR_WEBHOOK_SECRET")
    ```
  </Tab>
  <Tab title="JavaScript">
    ```javascript
    const crypto = require("crypto");

    function verifySignature(payload, signatureHeader, secret) {
      const expected =
        "sha256=" +
        crypto
          .createHmac("sha256", secret)
          .update(payload)
          .digest("hex");

      return crypto.timingSafeEqual(
        Buffer.from(expected),
        Buffer.from(signatureHeader)
      );
    }

    // In your request handler:
    // payload         = req.rawBody               (Buffer or string)
    // signatureHeader = req.headers["meetly-signature"]
    // isValid         = verifySignature(payload, signatureHeader, "YOUR_WEBHOOK_SECRET")
    ```
  </Tab>
</Tabs>

## Retry Policy

If your endpoint returns a non-`2xx` HTTP status code, Meetly automatically retries delivery with **exponential backoff**:

| Attempt | Delay after previous attempt |
|---------|------------------------------|
| 1st retry | 1 second |
| 2nd retry | 5 seconds |
| 3rd retry | 30 seconds |
| 4th retry | 2 minutes |
| 5th retry | 10 minutes |

After 5 failed attempts, Meetly stops retrying and marks the event as undelivered. You can view and manually replay undelivered events from **Settings → Webhooks → Event Log**.
