The Action Items API gives you programmatic access to tasks and commitments automatically extracted from your meeting transcriptions. Each action item includes the original text, an assigned owner, an optional due date, a current status, and a confidence score indicating how certain Meetly's model is that the item represents a real commitment.

---

## List Action Items

<api-endpoint method="GET" path="/v1/action-items" />

Retrieve a paginated list of action items across your workspace. Use the available filters to scope results to a specific meeting, status, or assignee.

### Query Parameters

<ParamField query="meeting_id" type="string">
  Filter action items to a specific meeting. Example: `"mtg_01hx3k9p2w"`.
</ParamField>

<ParamField query="status" type="string">
  Filter by the action item's current status. Accepted values: `open`, `in_progress`, `done`.
</ParamField>

<ParamField query="assignee_email" type="string">
  Filter action items assigned to a specific person by their email address. Example: `"alice@example.com"`.
</ParamField>

<ParamField query="limit" type="integer">
  Maximum number of action items to return per page. Defaults to `20`. Maximum is `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor returned in the previous response's `next_cursor` field. Pass this value to fetch the next page.
</ParamField>

### Response Fields

<ResponseField name="data" type="array">
  Array of action item objects matching the applied filters. Each object shares the same shape as the Get an Action Item response.
</ResponseField>

<ResponseField name="has_more" type="boolean">
  `true` if additional pages of results exist.
</ResponseField>

<ResponseField name="next_cursor" type="string">
  Opaque cursor to pass as `cursor` in your next request. `null` when `has_more` is `false`.
</ResponseField>

### Example

<CodeGroup>

```bash cURL
curl --request GET \
  --url "https://api.meetly.ai/v1/action-items?meeting_id=mtg_01hx3k9p2w&status=open" \
  --header "Authorization: Bearer YOUR_API_KEY"
```

      "text": "Bob to resolve the authentication edge case in ticket ENG-412.",
      "assignee": { "name": "Bob Carter", "email": "bob@example.com" },

## Get an Action Item

<api-endpoint method="GET" path="/v1/action-items/{id}" />

Retrieve a single action item by its unique identifier, including full assignee details, due date, status, and confidence score.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the action item to retrieve. Example: `"ai_3vn8zq1lkp"`.
</ParamField>

### Response Fields

<ResponseField name="id" type="string">
  Unique identifier for the action item. Example: `"ai_3vn8zq1lkp"`.
</ResponseField>

<ResponseField name="meeting_id" type="string">
  ID of the meeting from which this action item was extracted.
</ResponseField>

<ResponseField name="text" type="string">
  The verbatim or lightly cleaned action item text as extracted from the transcript.
</ResponseField>

<ResponseField name="assignee" type="object">
  The person responsible for completing this action item, or `null` if no assignee was detected.

  <ResponseField name="name" type="string">
    Assignee's full name.
  </ResponseField>

  <ResponseField name="email" type="string">
    Assignee's email address.
  </ResponseField>
</ResponseField>

<ResponseField name="due_date" type="string">
  ISO 8601 date string for the action item's due date, or `null` if none was detected or set.
</ResponseField>

<ResponseField name="status" type="string">
  Current status of the action item. One of `open`, `in_progress`, or `done`.
</ResponseField>

<ResponseField name="confidence" type="number">
  Float between `0` and `1` indicating the model's confidence that this item is a genuine commitment. Values above `0.85` are considered high-confidence extractions.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the action item was created.
</ResponseField>

### Example

<CodeGroup>

```bash cURL
curl --request GET \
  --url https://api.meetly.ai/v1/action-items/ai_3vn8zq1lkp \
  --header "Authorization: Bearer YOUR_API_KEY"
```

```json Response
{
  "id": "ai_3vn8zq1lkp",
  "meeting_id": "mtg_01hx3k9p2w",
  "text": "Alice to complete staging sign-off by January 18th.",
  "assignee": {
    "name": "Alice Johnson",
    "email": "alice@example.com"
  },
  "due_date": "2024-01-18",
  "status": "open",
  "confidence": 0.97,
  "created_at": "2024-01-15T09:12:10Z"
}
```

</CodeGroup>

## Update an Action Item

<api-endpoint method="PATCH" path="/v1/action-items/{id}" />

Update the status, assignee, or due date of an action item. Only the fields you include in the request body will be changed — omitted fields remain unchanged.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the action item to update. Example: `"ai_3vn8zq1lkp"`.
</ParamField>

### Request Body

<ParamField body="status" type="string">
  New status for the action item. Accepted values: `open`, `in_progress`, `done`.
</ParamField>

<ParamField body="assignee" type="object">
  Replace the assignee with a new person. Pass `null` to clear the assignee entirely.

  <ParamField body="name" type="string">
    Assignee's full name.
  </ParamField>

  <ParamField body="email" type="string">
    Assignee's email address.
  </ParamField>
</ParamField>

<ParamField body="due_date" type="string">
  ISO 8601 date string for the new due date. Pass `null` to clear an existing due date. Example: `"2024-01-22"`.
</ParamField>

### Response Fields

The response is the full updated action item object. See [Get an Action Item](#get-an-action-item) for the complete field reference.

### Example

<CodeGroup>

```bash Mark as done
curl --request PATCH \
  --url https://api.meetly.ai/v1/action-items/ai_3vn8zq1lkp \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "status": "done"
  }'
```

```bash Reassign and set due date
curl --request PATCH \
  --url https://api.meetly.ai/v1/action-items/ai_3vn8zq1lkp \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "assignee": { "name": "Carol Smith", "email": "carol@example.com" },
    "due_date": "2024-01-22"
  }'
```

```json Response
{
  "id": "ai_3vn8zq1lkp",
  "meeting_id": "mtg_01hx3k9p2w",
  "text": "Alice to complete staging sign-off by January 18th.",
  "assignee": {
    "name": "Alice Johnson",
    "email": "alice@example.com"
  },
  "due_date": "2024-01-18",
  "status": "done",
  "confidence": 0.97,
  "created_at": "2024-01-15T09:12:10Z"
}
```

</CodeGroup>
